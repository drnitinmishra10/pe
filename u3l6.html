I. Course Objectives & Learning Outcomes

By the conclusion of this lecture, students will be able to:

  • CO1: Transition prompt engineering from an intuitive trial-and-error heuristic into an empirical optimization cycle.
  • CO2: Design quantitative evaluation suites utilizing Exact Match (EM), Semantic Similarity, F1 Score, and G-Eval (LLM-as-a-Judge).
  • CO3: Mitigate judge-model biases including position bias, length bias, and self-enhancement bias in automated evals.
  • CO4: Understand the working principles of automatic prompt optimizers and compilers (e.g., APE, DSPy teleprompters).

III. Core Technical Breakdown

1. The Prompt Optimization Loop

Prompt engineering is formalized as searching for the optimal prompt token sequence P* from prompt space Ω that maximizes the expected score S over dataset D:

P* = argmax E_{(x, y) ~ D} [ S( f(x; P), y ) ] P ∈ Ω +------------------------------------------+ | 1. EVALUATION DATASET | | Input (x) + Reference Ground Truth (y) | +------------------------------------------+ | v +------------------------------------------+ | 2. CANDIDATE PROMPT RUNNER | | Model(Input; Prompt_k) -> Prediction (ŷ) | +------------------------------------------+ | v +------------------------------------------+ | 3. SCORING & METRICS ENGINE | | Compute: Exact Match, F1, or LLM Judge | +------------------------------------------+ | Loss / Failure Feedback v +------------------------------------------+ | 4. OPTIMIZER / REFINER (APE/DSPy) | | Mutate Prompt -> Generate Prompt_(k+1) | +------------------------------------------+

2. Evaluation Metric Taxonomies

Metric Category Concrete Metrics Primary Strengths Critical Failure Modes
Deterministic Syntactic Exact Match (EM), Regex validation, JSON syntax checking. Zero compute cost, 100% deterministic, immediate feedback. Penalizes semantically correct answers that differ by a single token.
N-Gram Overlap ROUGE-1/2/L, BLEU, METEOR. Standardized across literature; handles n-gram recall and precision. Poor alignment with human reasoning; easily gamed by repetition.
Model-Based (LLM Judge) G-Eval, Pairwise Elo rating, Likert 1–5 scoring with CoT justification. Understands semantic nuance, tone, safety, and multi-faceted criteria. High API cost, stochastic evaluation, susceptible to verbosity bias.

IV. Classroom Engagement & Active Socratic Prompts

The Verbosity Bias Dilemma: "In empirical studies, LLM judges consistently score longer, more verbose responses higher than short, concise responses—even when the concise answer is mathematically more accurate. How does this reflect RLHF training, and how do we engineer prompts to neutralize this bias?"

Faculty Discussion Guide: Reinforcement Learning from Human Feedback (RLHF) heavily rewards comprehensive-looking answers. To counter this in evaluation systems, students should practice length-normalization strategies, explicitly penalize responses exceeding strict word caps in the judge rubric, and conduct pairwise assessments with length-equalized completions.

V. Formative Assessment & Hands-on Assignment

  1. Automated Evaluation Script: Assemble a dataset of 10 complex question-and-answer pairs. Write a Python script using an LLM to evaluate two competing system prompts using a standardized Likert rubric.
  2. Pairwise Swap Test: Implement pairwise evaluation between Prompt A and Prompt B. Run the evaluation twice with reversed presentation orders: (A, B) then (B, A). Measure how often the judge favors the first option simply because of positional precedence.
